01 / START SMALL

Your first task

  1. Open Workspace and choose an agent. Start with architect for a read-only inspection.
  2. Describe one outcome. Keep Offline demo checked to try the interface without a model service. Demo responses are scripted, not real reasoning.
  3. Select Run task. Follow Task activity, then open the Run library to inspect the record.

For real work, configure a provider in Connections and turn off Offline demo. Read requested writes, commands, and external-tool actions carefully before approving. A request you reject must not execute.

02 / MAKE THE WORK VISIBLE

Plan before you delegate

Select Plan this task first → beneath the task form. Nexus saves a proposal and a reusable plan-* team; it does not start the workflow. Inspect its steps, agents, dependencies, and assumptions in Task activity. Then choose the generated team and select Run task when you are ready.

Agent tool permissions still apply during execution. Command requests also need the run-level opt-in and the configured execution permission. Worktrees are optional isolation for coding tasks, not a substitute for reviewing changes.

03 / GIVE EACH ROLE A PURPOSE

Choose what an agent remembers

  1. Open Agents and select a role to load its definition.
  2. Under Memory for this agent, choose all, selected, or no project memories. Adjust the item and character limits and included layers.
  3. Inspect the full JSON definition and select Save agent. The agent’s memory permission must also be enabled; a loadout does not grant tools or permissions.

04 / REMEMBER DELIBERATELY

Useful context, with a trail

Use L1 for facts and decisions, L2 for summaries, and L3 for lasting preferences. Choose project scope or a single agent. In Recall preview, select the agent and task to see the context available to it.

Keyword search · local works without embeddings. Keywords + meaning adds configured semantic retrieval. To distill a completed run, select it in Run library and choose Extract memories. Review the provider request, then review each proposal in Memory. Drafts cannot be recalled until approved.

05 / CONNECT WITH INTENT

Research Harness, with boundaries

The optional Research Harness integration exposes selected context through approved MCP reader tools. Nexus reads from the Harness; it does not acquire its operator authority. Setup and grants are explicit. When the Harness changes, recheck compatibility and any pinned source fingerprints before trusting the connection.

Inspect returned provenance. Methods, task output, and lessons can inform work; they are not automatically admissible citations. Use source evidence and its citation metadata for claims that require support.

06 / THE BIG PICTURE

One runtime, several ways in

The same diagram is on About Nexus. Interfaces share the agent runtime, which coordinates model requests, permission-controlled tools, and local records. Cloud providers and external integrations are optional, but can receive context when you use them.

The same controls,
a smaller screen.

On narrow windows, navigation scrolls horizontally and panels stack vertically. Scroll below the task form for activity and approvals.

This is a mobile-sized browser test, not remote phone access. The dashboard binds to loopback on your computer. Do not expose it publicly or share its session URL.

The macOS window uses this same dashboard. Packaging and launch instructions are in the full user guide.

KEEP EXPLORING

From the terminal

From a source checkout with Node 22.18+ and Git installed:

npm install
npm start -- init
npm start -- doctor
npm start -- serve

Open the full loopback URL printed by serve, including its session-token fragment. For provider setup, imports, teams, integrations, memory commands, and recovery, see the full user guide (Markdown), also bundled as docs/user-guide.md.

Never put real keys in screenshots or committed configuration. Use environment-variable references for secrets. Imported agents and skills still need review; an integrity check is not a publisher guarantee.

BUILD YOUR WORKSPACE

Optional knowledge, review and illustration tools

Open Code map to explore a configured codebase-memory index. Review its source scope, allow the connection, then search a symbol and follow callers or callees. Source links open your current project files.

Use nexus extras install review for independent plan and implementation reviews, or nexus extras install anatomy for a technical SVG illustrator. The review team needs distinct author and reviewer models. Cortex setup also requires explicit local engine and brain paths; the brain stays outside the app.

In Connections, a detected key makes its account available. Choose a model and use Use this model to assign it. Local Ollama appears in the same picker and needs no API key; start its server and install a model first. Detection and model listing do not prove generation or tool compatibility. Setup details are in the full user guide.
