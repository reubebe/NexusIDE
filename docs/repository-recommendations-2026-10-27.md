# Repository recommendations and visualization requirement

**Reviewed:** 27 October 2026. **Historical status:** original proposals. Implementation status as of 28 October is recorded below; the original assessment is retained for provenance.

The user explicitly requested visualization capability. The proposed initial scope is interactive 2D charts, workflow and knowledge graphs, timelines, and export; 3D is optional when the data is spatial. This is a recorded product requirement, not a claim that the capability has shipped.

Reviewed upstream READMEs, selected skill/MCP/architecture/manifest files, and Nexus implementation boundaries. No upstream applications, installers, model downloads, or benchmarks were executed for this review. Repository links below pin the reviewed default-branch snapshot, not an approved release version. ## Integration order and acceptance

1. Build the shared visualization/artifact boundary and deeper skill-inspection path. Visual outputs should carry source data and timestamps; chart labels, units, and unavailable values must remain visible. Use validated specifications or isolated viewers rather than executing arbitrary agent-generated JavaScript inside the dashboard.
2. Add the screenshot/review workflow and selected Project files improvements. Check actual interactions as well as screenshots, including mobile layout, keyboard navigation, and failed requests.
3. Trial Graphify against the current Code map backend before adopting it. Compare source-grounded answers, stale-index handling, bounded query output, latency, and private-data exposure. No token-saving or accuracy claim is accepted from upstream marketing alone.
4. Keep audio/video and segmentation as optional workers with separately managed dependencies, credentials, model/data licenses, and file scopes. Evaluate each on synthetic or explicitly approved media before real projects.
5. For Reef-inspired improvements, run baseline/candidate behavior on comparable tasks; record rejects and rollback. Nexus's current supplied-measurement evaluator is not an autonomous learning system.

## Scanner comparison

Nexus's `nexus-static-v2` remains a lightweight local pattern check, not a SkillSpector port. Prior synthetic probes caught an obvious download-and-run command, missed an unhandled Python data-transfer form, and flagged benign documentation about `eval`. These demonstrate limitations; they are not a shared accuracy benchmark. A deeper adapter should preserve reports and incomplete-coverage signals, and it must not replace runtime permission checks.
