# Integration and connection audit — 2026-10-24

This audit covers the optional Cortex reader, independent review workflow,
Code map, Anatomy subset, and provider-discovery improvements. It does not
replace the earlier security review or certify the entire product for production.

## Changes

- **Cortex:** three read-only MCP tools, explicit local brain scope, pinned engine
  bytes, bounded output, redaction before pagination and source hashes. Protocol
  errors now return errors without terminating the process. Private brain contents
  and the Cortex engine are not distributed.
- **Independent review:** separate planning, plan review, build and inspection
  runs; distinct author/reviewer model identifiers; bounded revisions/requests;
  approval before building; evidence checked against the plan or source actually
  read in the review. Unsupported or invalid verdicts stop the workflow.
- **Code map:** source-scoped, consent-gated symbol and relationship navigation
  using the existing codebase-memory-mcp backend. No duplicate graph engine or
  upstream browser service was introduced. Both upstream response table formats
  are supported, and the workspace lease is released after connection failures.
- **Anatomy:** eight bundled files with MIT attribution, pinned upstream hashes,
  an offline SVG example and an optional non-executing illustrator agent.
- **Setup:** `nexus extras install cortex|review|anatomy` preserves existing
  agents/routes. Cortex input validation happens before writes. Initialization
  reports each of the 28 bundled agents once; four optional agents bring this
  configured workspace to 32 without changing fresh-install defaults.
- **Connections:** detected environment accounts are shown separately from saved
  routes and prior verification. Ollama is available in the normal picker without
  a key. Its bounded model-list request uses a fixed loopback endpoint. Research
  Harness informed the status separation; no Harness credentials or vault were
  imported. Existing `API_KEY2` through `API_KEY99` conventions remain.
- **Packaging:** Finder `.DS_Store` metadata is excluded without failing a build;
  private source patterns still fail packaging. Guides and catalog entries explain
  the scope, prerequisites and remaining limits.

## Live limitations

Gemini model discovery is not proof of completion access. The listed
`gemini-2.5-flash` returned HTTP 404 with and without the `models/` prefix. A
bounded `gemini-3.8-flash` check observed multiple tool calls but encountered HTTP
503 and reached its 90-second deadline before completing the tool round trip.
It remains unverified; no automatic account switch or route change was made.

A single actual independent-review attempt used local `gpt-oss:20b` for planning
and `qwen3:8b` for review on a disposable project. Planning completed, but the
reviewer cited a file it had not read in its fresh run. Nexus rejected the evidence
after three requests, before any build approval or write. The source remained
unchanged. This validates rejection behavior, **not** a successful four-stage live
workflow. Successful orchestration is covered by deterministic protocol fixtures;
model review quality and a full live approval remain to be demonstrated.

The Cortex reader currently requires POSIX filesystem support. External engines,
Python and model services remain separate installations. No new live Research
Harness research workflow, Windows GUI or cloud-provider sweep was performed.
The macOS build is ad-hoc signed, not Developer ID signed/notarized. Genuine
clean-machine acceptance and a consented production pilot remain release gates.

Unrelated local video changes were left untouched. Source commits and packaged
artifacts do not contain private `.nexus` state, API keys or Cortex brain data.
