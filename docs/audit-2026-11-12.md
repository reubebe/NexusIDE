## Architecture decision

Preserved native Node ESM execution, SQLite WAL state/indexes, static local frontend assets, Swift/AppKit/WKWebView host, CLI, VS Code/Zed adapters, optional MCP/ACP and official subscription adapters. Research Harness remains a separate optional integration. Studio remains a secondary workspace. No mandatory network service or dependency was added.

The application already separates runtime, provider routing, execution permissions, workflow scheduling, state persistence, project intelligence and interface adapters. Shared-workspace writers serialize; worktree stages hand off reports rather than implicitly merging files. Resume uses prior prose as untrusted context and does not replay tool calls. Checkpoint continuation verifies source/configuration fingerprints and claims a checkpoint exclusively.

[Updated Astryx assessment](astryx-assessment.md) examines pinned upstream 0.7.15, React 19, TypeScript, Vite and component extraction. Retain native modules and shared theme variables. The observed defects did not require a framework migration. No React island was built because a compelling advantage was not established; comparative framework bundle/performance and WKWebView measurements remain unperformed. The implemented native timeline is tested directly; no framework superiority claim is made.

## Confirmed defects and corrections

| Finding | Root cause and correction | Regression evidence |
| --- | --- | --- |
| False successful completion after unsuccessful tools | A no-tool model reply unconditionally completed the run. Track unresolved calls using canonical argument hashes and reject terminal success while unresolved actions remain. Successful identical retries clear only their matching unresolved call, retaining attempt history. | `execution-outcomes.test.js`, negative development workflow, pilot and semantic-memory expectations. |
| Incorrect activity outcomes | Nonzero process returns and MCP error objects were labeled completed; arbitrary file text containing “declined” was labeled denied. Use structured control results, actual thrown errors and approval decisions before redaction. Include Git status, board and visualization refusals. | Process exit 7, denied writes, error-like source text, MCP/Git and approval cases. |
| Non-boolean visual consent | Truthy values could authorize image sharing/inference. Require boolean `true`; runtime approval callbacks now also require boolean `true`. | `visual-review.test.js` and `execution-outcomes.test.js`, no real provider calls. |
| Checkpoint approval could hang on cancellation | Resume did not check abort before prompting or race approval against cancellation. Pass the signal and use the existing abort helper. | Already-aborted and pending-approval tests in `workflow-checkpoints.test.js`. |
| Background requests outlived shutdown | Visual review, Code Map and deep scans had controllers absent from shutdown tracking; memory and discovery lacked propagated cancellation. Route them through the shared request lifecycle, reject late starts, propagate signals to discovery and avoid publishing a cancelled scan result. | `dashboard-cancellation.test.js` reproduced the old memory/visual-request failure and passes after the fix; provider signal tests. |
| Worktree lock authority differed by interface | Workflow and worktree-local CLI could store independent locks for the same canonical workspace under different state roots. Use workspace-owned exclusion while retaining parent visibility and guarded recovery. | `workspace-lock-authority.test.js`: cross-interface races, paired stale recovery, missing worktree, changed records and registration rollback. |

Completion is deliberately conservative: a successful alternative with different arguments does not automatically prove an earlier failed action irrelevant or fulfilled. Such a run remains failed/incomplete and requires inspection and a continuation task. The runtime cannot determine whether every natural-language requirement was attempted. `completed` still means the execution loop finished without unresolved recorded failures; it does **not** certify task correctness. Tests, code inspection and human acceptance remain distinct.

## Agent execution and benchmarks

New `test/development-workflow.test.js` provides a reproducible loopback-provider fixture. Three explicitly routed agents inspect faulty addition, receive workflow/write/command approval, change only the implementation, run actual Node acceptance tests, then inspect the source and Git diff with upstream reports. Five assertions fail before the edit and pass afterward; the test file hash stays unchanged. Eight deterministic model requests complete the successful case, and locks are released. A declined write preserves the original file and prevents tester/reviewer stages even when the provider emits completion prose.

Existing tests cover sequential/parallel DAGs, dependency validation, isolated worktrees, conflicting writers, budgets, malformed responses, provider errors, cancellation, interrupted recovery, checkpoint claims and no-replay continuation. Independent-review policy tests exercise structured verdict validation. They do not establish independent real-model review effectiveness.

Benchmark coverage is intentionally bounded: code reading, bug repair, execution of pre-authored tests, source/diff review, handoffs, approval compliance, continuation, lexical/hybrid retrieval and injected failures. Open-ended feature implementation, model-generated test quality, representative real-repository regression rates and real-model token efficiency remain unmeasured. No real-model comparison or memory-effectiveness improvement is claimed.

## Security and data integrity

Source review and isolated tests cover loopback token authentication, Host/Origin validation, CSP, protected filesystem paths, symlink/hardlink rejection, rechecking reviewed writes, bounded subprocess outputs, execution-time tool grants, approved MCP transport/calls, account isolation, redaction, worktree operations and SQLite snapshots. The new cancellation, explicit consent and cross-interface exclusion fixes strengthen existing boundaries without weakening authentication or CSP.

`npm audit --omit=dev --json` reported **zero known vulnerabilities** for the installed dependency graph on this audit date. This advisory result is not a complete security review of dependencies. No dependency was upgraded simply to obtain a different count.

Host commands and approved external tools still have host privileges; these are not OS sandboxes. Prompt-injection instructions cannot legitimately grant permissions, but no complete prompt-injection resistance is claimed. Hostile concurrent filesystem mutation, malicious third-party servers, all secret-output paths and every combination of concurrent recovery remain broader review topics. Security controls should be tested against representative deployments before release.

## Remaining priorities

1. **High, release gate:** complete signed/notarized clean-device acceptance with the exact final artifact; verify native UI, standard-user permissions, offline launch and actual upgrades.
2. **High, effectiveness gate:** explicitly authorize selected real providers and representative repositories, then evaluate task acceptance, recovery, regression rate, output evidence, request/token cost and memory usefulness independently of model prose.
3. **Medium:** improve recovery from valid alternative tool approaches with explicit, reviewable evidence. Avoid giving a model a flag that simply erases failure history.
4. **Medium:** expand adversarial filesystem/process tests and long-running concurrent workload/resource measurements; exercise installed optional graph and editor integrations.
5. **Medium:** full keyboard/VoiceOver/native visual audit, populated error/approval states and accessibility-tree checks beyond sampled control names and contrast.
6. **Deferred:** React/Astryx/TypeScript/Vite migration, additional indexing engines and larger media dependencies. None had measured benefit sufficient to offset the migration and security surface in this audit.
